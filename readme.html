Research, plan, connect, configure, and verify QuipBot without exposing credentials to the agent.

For: WordPress site owners and developersActs on: QuipBot setuppublic alpha
The problem

A useful chatbot needs grounded business knowledge, approved wording, consent, escalation rules, and a testable launch decision.

Chat-based setup often tempts people to paste WordPress passwords or provider keys into the AI conversation.

This skill separates human authorization from agent work and stores only non-secret, reviewable setup artifacts.

Public alpha
Research, questions, planning, and manual verification work now. WordPress writes remain blocked until the stable public API and OS-native helper ship.

Safety boundaries
No WordPress passwords, Application Passwords, provider keys, or tokens in chat.
No browser automation, SSH, XML-RPC, direct database writes, or internal admin routes.
No paid capability without entitlement and no go-live without explicit approval.
